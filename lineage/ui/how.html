Lineage. How the long-term memory works

The processor is a genetic search over small DAGs of LLM agents. The memory is MongoDB Atlas: every agent, every combination tried, every node run and every event. Each step of the loop checks the memory first, so a search can run for days, stop, resume, and never pay twice for the same work.

The processor

Each structure is a small DAG of agents (at most 6 nodes, depth 3). An agent's identity is its traits: role, brief, model and tools. The generator mutates the best structures, and an LLM proposes new ones from a summary of the memory.

The worklog

structures records every combination ever tried, keyed by a canonical hash. The same DAG drawn differently hashes the same, and a unique index turns "have we tried this?" into one lookup.

The node cache

modules stores each node's output under H(agent, inputs). When a new structure shares a prefix with an old one, those nodes are reused, not rerun. The dashed nodes in the UI are these reuses.

Measured

Same budget, memory ON vs OFF: the same best fitness (0.91 vs 0.92) with 62 tool calls instead of 143, and zero wasted repeats vs four.
